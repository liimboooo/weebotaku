# AnimeWch — Full Project Context + Session Log

## Project Overview
Anime tracking & social platform. Browse/search anime/manga, build watchlists, write reviews/ratings, manage tier lists, follow friends, get news/episode alerts, and watch together via LiveKit rooms. Arabic-focused streaming sources (ristoanime, anime3rb, witanime) with multi-source fallback.

## Tech Stack
- **Frontend**: React 19, react-router-dom 7, Tailwind CSS 4, framer-motion, LiveKit Client, Socket.IO Client, Lucide icons, Swiper
- **Backend**: Express 4, Mongoose (MongoDB Atlas), Socket.IO 4, JWT auth, LiveKit Server SDK, node-fetch, cheerio, wreq-js (CF bypass), helmet, rate-limit, nodemailer, speakeasy (2FA), web-push
- **Infrastructure**: Vercel (FE + BE as serverless funcs), MongoDB Atlas, LiveKit Cloud, Cloudflare Worker (CF bypass proxy)

## Architecture

### Frontend (CRA 5 — `frontend/`)
- **Routing** (`App.js`): Public routes: `/`, auth pages. App routes: `/home` (feed), `/browse/anime`, `/browse/manga`, `/anime/:id` (+ `/anime/:id/info`), `/manga/:id`, `/search`, `/news`, `/watchlist`, `/profile/:username`, `/settings`, `/history`, `/friends`, `/leaderboard`, `/watch-together`, `/arena`, `/arena/tier-lists`, `/feeds/amvs`, `/system/rules`, `/report`
- **Services** (`frontend/src/services/`):
  - `socket.js` — Global WebSocket client (Socket.IO). On Vercel (detected via `REACT_APP_API_URL` existence), falls back to 5s HTTP polling. Dispatches `CustomEvent('server-notification')` and `CustomEvent('friend-status-changed')`. Provides `joinAnimeRoom`/`leaveAnimeRoom`.
  - `notificationService.js` — Maps notification types to user setting keys (e.g. `comment_reply` → `['communityActivity', 'commentReplies']`)
  - `friendService.js` / `roomService.js` / `commentService.js` / `authService.js` / `animeApi.js` — API wrappers
  - `animeApi.js` — Multi-source search fallback chain: ristoanime → anime3rb → witanime → anitaku → consumet → anipub → embed. Uses codetabs public CORS proxy for Cloudflare-protected sources.
  - `storage.js` — LocalStorage-backed watchlist sync (`syncFromBackend` on app mount)
- **Key Pages**:
  - `AnimeDetail.jsx` — Anime page with comments, joins Socket.IO `anime:<id>` room, handles `new-comment` event, scrolls to `?comment=` param on mount
  - `ProfilePage.jsx` — Shows user profile, watchlist tabs, stats, share button, friend follow/accept/reject buttons + Watch Together button for friends
  - `WatchTogetherCreative.jsx` — LiveKit room viewer with URL source support (YouTube/Twitch/direct video), chat, room list. Handles `?room=` auto-join.
  - `FriendsPage.jsx` — Friends list management
  - `Home.jsx` — Feed/discover page
  - `SettingsPage.jsx` — User settings (notifications, appearance, etc.)

### Backend (Express — `backend/`)
- **Entry**: `server.js` — Connects MongoDB, starts Express, `initIO(server)` for Socket.IO
- **Socket.IO** (`socket.js`): JWT auth middleware, `user:<id>` rooms for targeted emits, `anime:<id>` rooms for comment broadcasts. Path: `/api/socket`
- **Models**: User, Comment, Friendship, Notification, Room, Review, TierList, News, Report, Sync
- **Controllers**:
  - `commentController.js` — CRUD, broadcasts `new-comment` to anime room, creates notifications for replies/likes
  - `friendController.js` — Send/accept/reject/remove, creates notifications, emits `friend-status` socket event
  - `roomController.js` — CRUD for LiveKit rooms, LiveKit token generation, `inviteUserId` support → creates `room_invite` notification
  - `notifyHelper.js` — `emitNotification(userId, notif)` emits to `user:<id>` socket room
  - `authController.js` — Register/login/verify-email/forgot-reset-password, OAuth sync (MAL/AniList)
  - `notificationController.js` — List/mark-read/mark-all-read notifications
  - `reviewController.js` / `tierlistController.js` / `reportController.js` / `leaderboardController.js`
- **Middleware**: sanitize (XSS), auth (JWT)
- **Routes**: All mounted under `/api/` in `app.js`

### Notification System
- **Backend**: `Notification` model with types: `comment_reply`, `comment_like`, `review_like`, `friend_request`, `friend_accepted`, `friend_online`, `system_update`, `new_feature`, `recommendation`, `room_invite`. Created in controllers, emitted via `notifyHelper.js` → Socket.IO `notification` event to `user:<id>` room.
- **Frontend Socket.IO path**: Receives `notification` event → dispatches `CustomEvent('server-notification')` → Header/ProfilePage listen. On Vercel (polling), polls `GET /api/notifications` every 5s, dispatches same CustomEvent.
- **User settings**: `NOTIF_TYPE_SETTING_MAP` in `notificationService.js` maps types to user preference keys.

### Real-Time Communication Patterns
| Feature | Socket (Dev) | Polling (Vercel) | CustomEvent |
|---------|-------------|-------------------|-------------|
| New comment on anime page | `new-comment` → `anime:<id>` room | N/A (anime page live) | — |
| Friend status change | `friend-status` → `user:<id>` room | `pollFriendStatus()` every 5s via API | `friend-status-changed` |
| Notification arrival | `notification` → `user:<id>` room | `pollNotifications()` every 5s via API | `server-notification` |
| Friend online | `friend-online` (future) | Not yet | Not yet |

### 2. Real-Time Friend Status
- `emitFriendStatus(targetUserId, peerUserId, status, friendshipId)` helper in `friendController.js`
- Called on every friend action: `sendRequest` (→ `pending`), `acceptRequest` (→ `accepted`), `rejectRequest` (→ `none`), `removeFriend` (→ `none`)
- Emits `friend-status` event to `user:<targetUserId>` room via Socket.IO
- Frontend `socket.js`: listens for `friend-status` event, updates `friendStatusCache` (keyed by userId), dispatches `CustomEvent('friend-status-changed')`
- `ProfilePage.jsx`: listens for `friend-status-changed` event, updates `friendStatus` state + falls back to API fetch on `server-notification` event with `friend_accepted` type
- `setPolledRemoteUserId(uid)` sets module-level variable for polling fallback

### 3. Vercel Fixes (WebSocket → HTTP Polling)
- **Socket.IO path mismatch**: Server used default `/socket.io/`, client used `/api/socket/`. Fixed: server now also uses `path: '/api/socket'`.
- **Vercel serverless limitation**: WebSocket connections fail on Vercel (no persistent connection). Frontend `socket.js` detects Vercel via `!!process.env.REACT_APP_API_URL`, skips Socket.IO, starts 5s HTTP polling fallback.
- **Polling fallback**: `pollNotifications()` → `GET /api/notifications`, tracks seen IDs in `lastNotifSeen` Set, dispatches `CustomEvent('server-notification')` for new ones. `pollFriendStatus()` → `GET /api/friends/status/${polledRemoteUserId}`, dispatches `CustomEvent('friend-status-changed')`.
- All components use the same `CustomEvent` listeners — transport-agnostic.
- Removed old 30s notification polling from `Header.jsx` (was using `startPolling(30000)` + `stopPolling`).

### 4. Friend Status Polling Fix
- **Original bug**: `pollFriendStatus()` hit two different endpoints per cycle and the wrong one — `GET /friends/status/:id` requires auth but was called without `remoteUserId`.
- **Fix**: Added module-level `polledRemoteUserId` set by `ProfilePage.jsx` via `setPolledRemoteUserId(remoteUserId)`. Polling uses this single user ID to call the correct endpoint.

## Notable Issues & Design Decisions
- **Socket.IO on Vercel is impossible** (no persistent server). Dual transport: WebSocket in dev, HTTP polling on Vercel. Same CustomEvent interface.
- **Friend status dual approach**: `friend-status` socket event (instant) + `server-notification` fallback (re-fetches via API when `friend_accepted` notification arrives).
- **Cloudflare-protected sources**: `ristoanime.co` bypassed via public `codetabs.com/v1/proxy` CORS proxy. Backend proxy and CF Worker both fail from datacenter IPs.
- **Notification links for comments**: Use `?comment=<id>` param because comments render on `/anime/:id` (AnimeDetail), not `/anime/:id/info` (AnimeInfo).
- **Frontend build**: Passes `npm run build` with zero errors (pre-existing warnings only).
